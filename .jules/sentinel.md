## 2025-05-18 - Enforce Secure File and Directory Permissions in SqliteEventStore
**Vulnerability:** SqliteEventStore database files, ownership lock files, pre-existing SQLite sidecar files (`-journal`, `-wal`, `-shm`), or parent directories residing in untrusted locations (e.g. `/tmp` with `0o777`) could be created or owned by an untrusted user UID or have group/world permissions, allowing unprivileged local users to read, tamper with, or create unauthorized sidecars before or during SQLite operation.
**Learning:** Standard `mkdir(parents=True)` applies default umask (e.g., `0022`), creating new directories with `0755` mode which fails strict security mode checks unless created with explicit `0o700` mode and `chmod(0o700)`. Checking existing permissions alone is insufficient without securing new directory creation.
**Prevention:** In `SqliteEventStore`, create new parent directories with explicit `0o700` mode and verify `st_mode & 0o077 == 0` AND `st_uid == os.geteuid()` on the store's parent directory, database file, lock file, and pre-existing sidecar files (`-journal`, `-wal`, `-shm`) before establishing the SQLite connection.
